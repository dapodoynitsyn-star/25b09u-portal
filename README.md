# Портал 25.Б09-ю — Юридический факультет СПбГУ

Современный сайт группы: главная страница, расписание, домашние задания,
библиотека материалов, календарь сессии и объявления старосты, с
защищённой админ-панелью. На телефоне — отдельная нижняя панель навигации
(как в мобильных приложениях), на ПК — верхнее меню; вёрстка везде
адаптируется под ширину экрана.

**Стек:** React + TypeScript + Vite + Tailwind CSS + Framer Motion + Lucide Icons + Firebase (Auth, Firestore, Storage).

Сайт полностью рабочий сразу после установки зависимостей — даже без
Firebase: данные хранятся в localStorage браузера (демо-режим) и заранее
заполнены примерами. Как только вы подключите свой проект Firebase, сайт
автоматически переключится на реальную базу данных в реальном времени.

Расписание занятий на сайте подгружается напрямую с официального сайта
СПбГУ ([timetable.spbu.ru](https://timetable.spbu.ru)) — вручную его
поддерживать не нужно. Подробности — в разделе 2.

## 2. Расписание с официального сайта СПбГУ

И страница «Расписание» (по неделям), и раздел «Занятия» на странице
«Календарь» получают данные напрямую из официального API timetable.spbu.ru
для группы **25.Б09-ю** (id группы — `429104`, взят из ссылки
`https://timetable.spbu.ru/LAWS/StudentGroupEvents/Primary/429104/...`).
Ничего вручную обновлять не нужно.

Идентификатор группы задан в `src/services/officialSchedule.ts`
(`SPBU_GROUP_ID`) — если группа сменит номер, достаточно поменять его там.

**Почему прямой запрос из браузера обычно не работает:** у API СПбГУ нет
CORS-заголовков для сторонних сайтов. Чтобы это не мешало, сайт всегда
обращается к своему же относительному адресу `/api/schedule`, а не
напрямую к timetable.spbu.ru — и этот адрес работает по-разному в
зависимости от того, где открыт сайт, но браузер CORS не блокирует ни в
одном случае:

1. **`npm run dev` (разработка)** — Vite сам проксирует `/api/schedule` на
   timetable.spbu.ru (настроено в `vite.config.ts`, секция `server.proxy`).
   Работает сразу после установки зависимостей, донастраивать не нужно.
2. **Деплой на Vercel** — тот же путь `/api/schedule` обслуживает
   serverless-функция `api/schedule.js`, которая делает запрос на сервере.
   Тоже работает автоматически.
3. **Статический хостинг без сервера (GitHub Pages)** — пути `/api/schedule`
   там нет, поэтому сайт последовательно пробует прямой запрос к
   `timetable.spbu.ru`, а затем — запасной публичный CORS-прокси
   (`allorigins.win`).

Если ни один способ не сработал (нет интернета, СПбГУ проводит
технические работы и т.п.), «Расписание» покажет резервные данные из
админ-панели (вкладка «Расписание»), а «Календарь» — только события из
одноимённого раздела, без занятий. Сайт сообщит об этом прямо на странице:
жёлтый значок на «Расписании», приглушённая подпись на «Календаре».

**Если расписание не грузится:** откройте консоль браузера (F12) на
странице «Расписание» или «Календарь» — при неудаче там появится
подробность ошибки. Формат ответа API нигде официально не документирован —
интеграция написана по данным открытых сторонних проектов
(`spbu-timetable/timetable` и др.) и разбирает несколько вероятных
вариантов названий полей; если у СПбГУ они отличаются, поправить нужно
функцию `normalize()` в файле `src/services/officialSchedule.ts`
(в дев-режиме туда же в консоль выводится необработанный ответ API, если
разбор не нашёл в нём занятий).

## 4. Подключение Firebase

1. Создайте проект на [console.firebase.google.com](https://console.firebase.google.com).
2. **Authentication** → Sign-in method → включите «Email/Password». Создайте
   пользователя (email старосты) во вкладке Users — это и будет вход в
   админ-панель.
3. **Firestore Database** → создайте базу (production mode). Коллекции
   `users`, `homework`, `subjects`, `schedule`, `announcements`,
   `calendar`, `materials` создаются автоматически при первой записи —
   отдельно создавать их не нужно.
4. **Storage** → включите хранилище для файлов заданий и материалов.
5. Project settings → General → Your apps → Web app → скопируйте
   конфигурацию SDK.
6. Скопируйте `.env.example` в `.env` и вставьте свои значения:

   ```bash
   cp .env.example .env
   ```

7. Перезапустите `npm run dev`. Сайт автоматически определит, что Firebase
   настроен (`isFirebaseConfigured` в `src/lib/firebase.ts`), и начнёт
   работать через Firestore/Auth/Storage вместо демо-режима.

### Правила безопасности (пример)

Настройте Firestore Rules так, чтобы читать мог кто угодно, а писать —
только авторизованный староста:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{collection}/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}
```

Аналогично для Storage Rules (`allow read: if true; allow write: if request.auth != null;`).

## 5. Публикация

### Vercel (рекомендуется)

1. Залейте проект на GitHub.
2. На [vercel.com](https://vercel.com) → New Project → выберите репозиторий.
3. Framework Preset определится как Vite автоматически.
4. Добавьте переменные окружения из `.env` в настройках проекта (Environment Variables).
5. Deploy.

### GitHub Pages

1. В `vite.config.ts` `base` уже установлен в `'./'` — подходит для GitHub Pages.
2. Соберите проект: `npm run build`.
3. Опубликуйте содержимое папки `dist` в ветку `gh-pages`, например через
   пакет `gh-pages`:

   ```bash
   npm install -D gh-pages
   npx gh-pages -d dist
   ```

4. В настройках репозитория GitHub → Pages → выберите ветку `gh-pages`.

## 6. Структура проекта

```
api/
  schedule.js   serverless-прокси к API СПбГУ (работает на Vercel)
public/
  emblem.png    герб юридического факультета — логотип сайта и favicon
src/
  components/   переиспользуемые UI-компоненты (layout, ui, admin)
  hooks/        useAuth, useTheme, useToast, useCollection, useOfficialSchedule
  lib/          firebase.ts, utils.ts, demoData.ts, localStore.ts
  pages/        страницы сайта + pages/admin — вкладки админ-панели
  services/     dataService.ts (Firestore/демо-данные) и
                officialSchedule.ts (интеграция с timetable.spbu.ru)
  types/        общие TypeScript-типы
```
